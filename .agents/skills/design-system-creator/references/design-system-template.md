# Design System Specification Template

This template outlines the comprehensive structure for `DESIGN.md` generated by the `design-system-creator` skill.

```markdown
# Design System Specification

## 1. Design Philosophy
[The core rationale behind the visual language. Explains WHY visual decisions exist so future AI sessions understand the intent.]

- **Core Tenet 1**: [e.g., Visual hierarchy is driven by typography, spacing, and contrast rather than decorative fluff.]
- **Core Tenet 2**: [e.g., Generous whitespace and restrained color usage maintain cognitive calm.]
- **Core Tenet 3**: [e.g., Motion is functional and purposeful, never purely decorative.]

## 2. Technology & Stack Constraints
- **Framework**: [Next.js App Router / React / Vue / Vite / Vanilla HTML]
- **Styling Architecture**: [Tailwind CSS / Vanilla CSS / CSS Modules / Styled Components]
- **Component Library**: [shadcn/ui / Radix UI / Custom / Polaris]
- **Icon Set**: [Lucide React / Heroicons / Custom SVG]
- **Animation Strategy**: [Framer Motion / GSAP / CSS Transitions]

### Implementation Rules for AI Sessions
- [Rule 1: e.g., Prefer existing shadcn primitives over building custom wrappers]
- [Rule 2: e.g., Use Tailwind design tokens rather than arbitrary pixel values like `w-[287px]`]
- [Rule 3: e.g., Keep state logic separated from visual presentation components]

## 3. Color System & Tokens
### Base Palette & Functional Tokens
- `--background`: [Hex / HSL value] — Page canvas background
- `--foreground`: [Hex / HSL value] — Primary text & icon color
- `--card`: [Hex / HSL value] — Container / surface background
- `--card-foreground`: [Hex / HSL value] — Card content text color
- `--primary`: [Hex / HSL value] — Key brand focus / interactive action
- `--primary-foreground`: [Hex / HSL value] — Text on primary surfaces
- `--secondary`: [Hex / HSL value] — Secondary buttons & subtle highlights
- `--secondary-foreground`: [Hex / HSL value] — Text on secondary surfaces
- `--muted`: [Hex / HSL value] — Subdued surfaces and secondary text
- `--muted-foreground`: [Hex / HSL value] — Subdued helper labels / icons
- `--border`: [Hex / HSL value] — Card and divider borders
- `--ring`: [Hex / HSL value] — Focus outlines & active indicators

### Semantic Status Tokens
- **Success**: `--success` [Hex/HSL] — Positive state / completion
- **Warning**: `--warning` [Hex/HSL] — Caution / warning state
- **Error**: `--destructive` [Hex/HSL] — Error / destructive action
- **Info**: `--info` [Hex/HSL] — Informational notices

## 4. Typography System
- **Font Families**:
  - Headings: `[Font Family]` (e.g., Geist Sans, Inter, Playfair Display)
  - Body: `[Font Family]` (e.g., Geist Sans, Inter)
  - Monospace / Data: `[Font Family]` (e.g., JetBrains Mono, Fira Code)
- **Type Scale**:
  - `h1`: [Size / Weight / Letter-spacing / Line-height] — Page titles
  - `h2`: [Size / Weight / Letter-spacing / Line-height] — Section headers
  - `h3`: [Size / Weight / Letter-spacing / Line-height] — Subsections / Card titles
  - `body`: [Size / Weight / Line-height] — General copy
  - `small / caption`: [Size / Weight / Letter-spacing] — Subtext / Metadata

## 5. Spacing & Spatial Grammar
- **Base Grid Scale**: 4px / 8px incremental system (`rem` units preferred)
- **Container Max Widths**:
  - Standard App Page: `1200px` (`max-w-7xl`)
  - Content / Article / Form: `768px` (`max-w-3xl`)
  - Modal / Dialog: `512px` (`max-w-lg`)
- **Padding & Gap Standards**:
  - Page padding: `px-4 sm:px-6 lg:px-8`
  - Section vertical gap: `space-y-8` or `space-y-12`
  - Card internal padding: `p-6` (desktop), `p-4` (mobile)

## 6. Component Principles
- **Buttons & Interactive Controls**:
  - Maximum 3 visual variants: Primary (solid accent), Secondary (ghost/outline), Destructive.
  - Hover states use subtle opacity / shade transitions, not scale bounces.
- **Cards & Surfaces**:
  - Flat surfaces with thin borders preferred over heavy drop shadows.
  - Border radius scale: `rounded-lg` (8px) or `rounded-xl` (12px) consistently across app.
- **Data Tables & Lists**:
  - Subtle row hover highlights.
  - Explicit column alignments: text left-aligned, numbers right-aligned.

## 7. Composition & Engineering Rules
- **Encapsulated Spacing**: Components must manage internal padding; parent layouts manage outer positioning and gaps.
- **Token Compliance**: Do NOT introduce ad-hoc hex values (`#3a82f6`) in component code. Use CSS/Tailwind variables.
- **Component Reuse**: Inspect existing primitives before creating duplicate UI wrappers.

## 8. Responsive Layout Principles
- Mobile layouts collapse multi-column grids into single-column vertical flows intentionally.
- Navigation simplifies to drawer/hamburger or bottom bar on mobile.
- Typography scales down down proportionally on small viewports without breaking touch targets.
- Minimum touch target for interactive elements is `44x44px`.

## 9. Motion & Interaction Guidelines
- **Duration**: Fast for micro-interactions (150ms-200ms), standard for transitions (300ms).
- **Easing**: `cubic-bezier(0.16, 1, 0.3, 1)` (smooth ease-out).
- **Intentionality**: Motion serves feedback and spatial context; never animate purely to fill quiet space.
- **Reduced Motion**: Respect `prefers-reduced-motion` media queries.

## 10. Practical Guardrails (Do / Don't)
### Do:
- Establish strong typographic contrast before adding color.
- Maintain consistent border-radius and spacing tokens.
- Use explicit semantic HTML elements (`main`, `section`, `nav`, `article`).

### Don't:
- Add arbitrary inline CSS styles or un-themed hex codes.
- Nest cards inside cards inside cards (avoid card-in-card fatigue).
- Use decorative gradient text or pulsing pill badges unless explicitly defined in `BRAND_PHILOSOPHY.md`.
```
